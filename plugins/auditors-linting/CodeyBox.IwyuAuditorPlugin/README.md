# CodeyBox: Include-What-You-Use C/C++ Analyzer

Auditor plugin wrapping [include-what-you-use](https://include-what-you-use.org/)
(IWYU): it drives `iwyu_tool -p <compile_commands.json> .`, which runs
`include-what-you-use` once per translation unit recorded in an explicit
Clang JSON compilation database, and reports each "should add" / "should
remove" suggestion as an advisory audit finding. Read-only by design — the
auditor never runs `fix_includes` and never rewrites sources; include edits
belong to the work phase.

## What it reports

- One finding per suggested include or forward-declaration change. The
  title carries the rule id and the suggestion (e.g.
  `iwyu-add: add missing include or forward declaration: '#include <vector>  // for std::vector'`);
  the description carries the tool, rule, tool-reported level, location,
  and full message.
- `iwyu-add` — a `#include` or forward declaration the file needs but does
  not directly declare (a direct-include omission).
- `iwyu-remove` — a `#include` or forward declaration IWYU proved unneeded
  (an unnecessary C/C++ dependency). The finding location carries the first
  source line of the reported range.
- `iwyu-coverage` — a single informational record per run: how many files
  received an IWYU verdict. It never gates and can be hidden via
  `ExcludedRules` or `MinimumSeverity: warning`.
- **Diagnostics in headers.** IWYU reports verdict blocks for a translation
  unit's associated headers too; their findings carry the header path. The
  same suggestion re-emitted through several translation units is reported
  once.
- **Gate behaviour: advisory — never blocking.** IWYU has no severity
  vocabulary; suggestions map to `Warning` and the coverage record to
  `Info`. A run that analysed every selected translation unit *passes* even
  with violations — findings inform the rework loop, they do not block it.
  There is no mode in which untidy includes fail the audit; audit failures
  are always infrastructure (the check could not be verified).

## Prerequisites — the compilation database

IWYU cannot analyse a file without its real compile flags, so this auditor
requires an explicit Clang JSON compilation database. Generate one before
the audit runs — e.g. `cmake -DCMAKE_EXPORT_COMPILE_COMMANDS=ON`, `ninja`
with `compdb`, or `bear`/`intercept-build` — and make it reachable inside
the audit sandbox (committed, generated by a baseline step, or staged by
provisioning). Then set:

```json
{
  "CodeyBox": {
    "Plugins": {
      "codeybox.iwyu": { "CompilationDatabase": "build/compile_commands.json" }
    }
  }
}
```

The value may be the database file itself or the directory containing it
(both `build` and `build/compile_commands.json` work). A repository-relative
path must canonicalize inside the audited worktree — a repo-controlled
symlink escaping the tree fails closed. An absolute path is treated as
operator-owned and may live anywhere. The database file is read through a
bounded read (`MaxOutputBytesPerStream` caps it) and parsed before the scan:
a missing path, a directory without `compile_commands.json`, malformed
JSON, an entry with no usable `file`, more than
`MaxCompilationDatabaseEntries` entries, or a database listing zero
in-worktree translation units are all deterministic infrastructure failures
— a vacuous run is never a pass.

**Source containment.** The scan selects the worktree root (`.`) as
iwyu_tool's only source selector: a compilation entry runs only when its
`file` — resolved against its `directory` and canonicalized — stays inside
the audited tree. Entries pointing outside (generated build output, system
trees) are counted and logged per run, never analysed.

## What it cannot see

- **Repositories without a compilation database.** The auditor is an
  infrastructure failure until `CompilationDatabase` is configured — there
  is no heuristic fallback.
- **Headers and TUs absent from the database.** IWYU only analyses the
  translation units the database names (contained to the worktree). A
  database that omits sources narrows coverage — the `iwyu-coverage` record
  and the per-finding locations show exactly which files received verdicts.
- **A translation unit that fails to compile.** IWYU exits 1 on an
  unrecoverable frontend error, iwyu_tool propagates the worst child exit,
  and the run is infrastructure — partial coverage is never reported as a
  pass. The failing unit's clang diagnostics appear in the captured output.
- **Pre-0.17 exit codes.** IWYU 0.16 and older returned `2 + edits`; those
  releases fail the version pin.
- **Out-of-worktree report paths.** A reported path that stays absolute (or
  still carries `..`) after normalization is re-marked with a `file://`
  prefix so it can never read as a repository-relative location; the
  finding still reports it.
- **Repository-controlled suppression.** IWYU honors `// IWYU pragma: keep`,
  `// IWYU pragma: export`, and `// IWYU pragma: private` comments authored
  inside the audited repository — there is no flag to disable them, so a
  pragma-silenced include never becomes a finding. Mapping files
  (`*.imp`) referenced by compile flags shape suggestions the same way.
  Both are visible in the audited diff.
- **More than `MaxFindings` findings.** Excess is dropped and the
  truncation is reported in the raw output.

## Exit codes and failure classification

iwyu_tool's exit is the worst child exit (verified against IWYU 0.21 —
**not** assumed from the common table). The scan deliberately does not pass
`-Xiwyu --error`, so the convention stays meaningful:

| Exit | Meaning | Classification |
|---|---|---|
| `0` | Every selected translation unit analysed (clean, or violations reported) | Verdict — pass or advisory findings |
| `0` with empty/unrecognised output | No verdict records — nothing actually ran | Infrastructure (`AuditUnavailableException`) |
| `1` | A translation unit hit an unrecoverable error, or the driver failed (bad database, bad flags) | Infrastructure — partial coverage is never a pass |
| `126` / `127` | `iwyu_tool` not executable or not found | Infrastructure |
| anything else | Unknown convention | Infrastructure (fails loud, never a pass) |

Missing `iwyu_tool` **or** `include-what-you-use` is always an
infrastructure failure naming the tool — never a passing audit.

## Version pinning

The auditor is pinned to **IWYU `0.21.0`** (`ExpectedVersion` in scoped
config — Ubuntu noble's `iwyu` package 8.21, whose
`include-what-you-use --version` prints
`include-what-you-use 0.21 based on …`; two-part IWYU releases normalize to
the three-part pin form). IWYU's analysis and report grammar change between
releases, so an unpinned tool would change findings under you: the auditor
probes `include-what-you-use --version` before every run and reports an
infrastructure failure on any other version. Each IWYU release builds
against one LLVM/Clang, so the IWYU pin pins the toolchain pair.

`IWYU_BINARY` is stripped from the scan and probe environments — iwyu_tool
honors it as the engine path, which would bypass this pin.

The tool requirements declare **`AptPackage = "iwyu"`** for both binaries,
so baseline provisioning installs them via apt **only when this plugin is
enabled**. The Debian metapackage tracks the distro default release, so
keep the provisioned release and `ExpectedVersion` in step: after a
baseline upgrade that moves IWYU, update `ExpectedVersion` (e.g. to
`0.22.0` for iwyu 8.22 / LLVM 18) or hold the package — otherwise the
auditor fails closed until you do.

## Enabling

The plugin is **disabled by default** — it loads only when named in both
gates, and baseline provisioning installs/verifies `iwyu` only in that
state:

```json
{
  "CodeyBox": {
    "Plugins": {
      "Allowlist": ["codeybox.iwyu"],
      "Enabled": ["codeybox.iwyu"]
    }
  }
}
```

and per project under `Audit.Custom`:

```json
{ "Kind": "plugin", "PluginId": "codeybox.iwyu" }
```

## Configuration

Scoped under `CodeyBox:Plugins:codeybox.iwyu`, resolved per run
(hot-reloadable):

| Key | Default | Meaning |
|---|---|---|
| `CompilationDatabase` | — **required** | Repository-relative path to `compile_commands.json` or its directory (must canonicalize inside the worktree), or an operator-owned absolute path. Unset → deterministic infrastructure failure. |
| `ExpectedVersion` | `0.21.0` | Pinned IWYU release (`0.21` and `0.21.0` are equivalent). A different installed version fails closed as infrastructure. |
| `MaxCompilationDatabaseEntries` | `4096` | Upper bound on database entries; larger databases fail closed deterministically. |
| `MinimumSeverity` | `info` | Drop mapped findings below this severity (`info`, `warning`, `error`). |
| `IncludedRules` / `ExcludedRules` | — | Exact rule ids to keep/drop (`iwyu-add`, `iwyu-remove`, `iwyu-coverage`). |
| `ExcludePaths` | `vendor/`, `third_party/`, `node_modules/`, `dist/`, `build/`, `out/`, `coverage/`, `.venv/`, `venv/`, `__pycache__/` | Repo-relative paths dropped from findings — exact path, or directory prefix when trailing `/`. Filters reported findings only; it does not change which translation units run. Setting it replaces the default list. |
| `ExtraArguments` | — | Extra `iwyu_tool` options appended after the built argv (e.g. `-j,4` for parallel units, `-e,<path>` to exclude a subtree, `--verbose`, or `--` followed by `-Xiwyu` options). A `-p` flag here is rejected — use `CompilationDatabase`. `-Xiwyu --error`/`--error_always` after `--` is rejected: it renumbers the exit convention the classification depends on. Changing `-o/--output-format` or other report-affecting flags surfaces as an infrastructure failure when the parser can no longer find verdicts. |
| `TimeoutSeconds` | `300` | Per-run bound (the database probes share it under a 30 s cap). IWYU runs a full clang front-end per translation unit — raise it for large trees. Exceeding it is infrastructure, not a pass. |
| `MaxOutputBytesPerStream` / `MaxFindings` | `1 MiB` / `1000` | Output/result caps; overruns are reported as truncation. The stream cap also bounds the compilation-database read. |

**Repository trust posture.** The audited repository writes the compilation
database (its compile flags reach the clang front-end verbatim — the same
contract as clang-tidy's `-p`), and in-source pragmas (`// IWYU pragma:
keep` etc.) are honored with no off switch — a subject can shape
suggestions for its own file, which is the project's own build contract.
The auditor controls the boundary that matters: only in-worktree sources
are analysed, violations are advisory, and an unanalysable unit fails
loudly. The auditor runs under `AuditCapabilities.None` (no agent
credentials, no network).
